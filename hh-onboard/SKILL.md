# hh:onboard — Project Context Loading

Two modes, auto-detected by checking if `CLAUDE.md` exists in the project root.

## Mode A: Existing Project (CLAUDE.md exists)

**Goal:** Get AI up to speed in under 60 seconds.

### Step 1: Read Core Docs

Read these files in parallel:
- `CLAUDE.md` — project overview, architecture, commands, **rules from repeated mistakes** (if the project has these, they are the highest-priority constraints)
- `docs/error-log.md` — known errors and root causes (if exists — read this BEFORE touching any code)
- `docs/context/error-patterns.md` — error taxonomy by category, detection heuristics (if exists)
- `docs/Context.md` — domain knowledge, terminology (if exists)
- `docs/Constraints.md` — hard constraints (if exists)

### Step 2: Check State

Scan for recent activity signals:
- `docs/todo/INDEX.md` — what's pending?
- `docs/handoff/` — any unfinished handoff files?
- Git status — uncommitted changes? current branch?
- `docs/adr/INDEX.md` — recent decisions?

### Step 3: Summarize

Output a concise summary:
```
## [Project Name] — Current State

**What this project does:** [one line]

**Architecture:** [phases/modules, 1-2 lines]

**Recent work:** [from git branch / recent commits]

**Pending:** [from todo/INDEX.md, top 3 items]

**Known pitfalls:** [from error-log.md if exists — total errors, most recent, most severe category]

**Available skills:** hh:think hh:diagnose hh:experiment hh:visualize hh:schedule hh:undo hh:runbook

What should we work on?
```

## Mode B: New/Undocumented Project (no CLAUDE.md)

**Goal:** Bootstrap the complete documentation structure.

### Step 1: Assess Project

- Read key files to understand: tech stack, purpose, directory structure
- Identify target users and main workflows

### Step 2: Create Directory Structure

```
docs/
├── quick-start/
│   └── INDEX.md
├── handoff/
│   └── README.md
├── visualization/
│   └── README.md
├── todo/
│   ├── INDEX.md
│   ├── 0-urgent/
│   ├── 1-high/
│   ├── 2-medium/
│   └── 3-low/
├── Context.md
├── Constraints.md
├── error-log.md
└── adr/
    └── INDEX.md
```

### Step 3: Generate Core Files

**CLAUDE.md** — Use the template below (adapt to detected tech stack):

```markdown
# [Project Name]

[One-line purpose.]

## Quick Start

```bash
# Build / run / test commands
```

## Architecture

[High-level structure — phases, modules, data flow. Keep under 15 lines.]

## 文档导航

| 我要... | 去这里 |
|---------|--------|
| 了解项目怎么跑 | `docs/quick-start/` |
| 了解业务背景和术语 | `docs/Context.md` |
| 知道有哪些坑 | `docs/error-log.md` |
| 知道绝对不能做什么 | `docs/Constraints.md` |
| 看架构决策历史 | `docs/adr/INDEX.md` |
| 接手上一个 AI 的工作 | `docs/handoff/` |
| 看/确认 AI 生成的方案 | `docs/visualization/` |
| 看还有什么需求没做 | `docs/todo/INDEX.md` |

## Key Conventions

- [Convention 1]
- [Convention 2]
```

**docs/Context.md** — Fill in domain knowledge, terminology, data flow.

**docs/Constraints.md** — Hard constraints (what to NEVER do), soft constraints (avoid unless justified).

**docs/error-log.md** — Template with error categories.

**docs/adr/INDEX.md** — Decision log template.

### Step 4: Initialize Subdirectories

**docs/quick-start/INDEX.md:**
```markdown
# Quick Start Index

| Feature | Doc | Last Updated |
|---------|-----|---------------|
| (待添加) | | |
```

**docs/handoff/README.md:**
```markdown
# Handoff Documents

## Purpose
When a conversation is too long or switching agents, compress context for the next AI.

## When to Create
- User says "交接" or "handoff"
- Context window nearly full
- Switching to a different agent/tool for next phase

## Naming
`{YYYY-MM-DD}-{topic}.md`

## Content Requirements
1. Current progress (what's done, what's not)
2. Key file paths (with brief description of each)
3. Unfinished items (ranked by priority)
4. Known pitfalls / decisions made

## Lifecycle
- Create: during handoff
- Read: by next agent at session start
- Delete: after task is complete (or archive if reusable)
```

**docs/visualization/README.md:**
```markdown
# Visualization Artifacts

## Purpose
Store HTML/Markdown review artifacts generated by `hh:think` and `hh:visualize`.
These are for user review and approval — NOT implementation code.

## Naming Convention
- Design reviews: `idea-{topic}-{YYYYMMDD}.html`
- Data reports: `report-{topic}-{YYYYMMDD}.html`

## Lifecycle
1. Generated by skill
2. Auto-opened in browser for user review
3. User decides: keep (valuable) or delete (one-time review)
4. Should NOT be committed to git (add to .gitignore)

## Active Files
(List current files with brief description)
```

### Step 5: Report

Output what was created and suggest next steps:
```
## Documentation Bootstrapped

Created:
- CLAUDE.md (with doc navigation table)
- docs/Context.md, Constraints.md, error-log.md
- docs/quick-start/INDEX.md
- docs/handoff/README.md
- docs/visualization/README.md
- docs/todo/INDEX.md (with 4 priority directories)
- docs/adr/INDEX.md

**Next:** Run `hh:think` if you have a feature idea, or `hh:runbook` after implementing.
```

---

## Red Flags

- Skipping the CLAUDE.md check and always bootstrapping
- Skipping `docs/error-log.md` when it exists — this is the single most important file to avoid repeating known mistakes
- Creating docs without reading existing code first
- Writing overly detailed CLAUDE.md (>200 lines)
- Not updating .gitignore to exclude visualization/
